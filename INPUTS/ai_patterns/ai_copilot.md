# AI Copilot Pattern

## Purpose
Embed AI assistance into a user workflow to help people complete tasks faster, improve quality, and reduce cognitive load.

## When to Use
Use this pattern when users repeatedly draft, analyze, summarize, compare, document, or prepare outputs inside a business workflow.

## Typical Pain Points Addressed
- high_ops_costs
- slow_change
- inefficient_workflow
- manual_reconciliation
- knowledge_risk
- poor_customer_experience

## Business Capabilities Supported
- enterprise architecture management
- project and transformation management
- finance operations
- service management
- customer operations
- process management
- change management

## Technology Capabilities Required
- embedded AI assistance
- contextual retrieval
- prompt and template management
- identity and access management
- workflow integration
- content generation
- audit logging

## Typical Use Cases
- finance analyst copilot
- enterprise architect copilot
- project manager copilot
- process analyst copilot
- support agent copilot
- change manager copilot
- meeting and action summary copilot

## Operating Model Impact
- accelerates professional knowledge work
- standardizes draft quality
- reduces context switching
- requires clear approval boundaries
- shifts users from creating from scratch to reviewing and refining

## Data Requirements
- role context
- task context
- approved templates
- relevant source documents
- user permissions
- historical examples
- output quality criteria

## Integration Requirements
- Microsoft 365
- ServiceNow
- Jira
- CRM or ERP systems
- document repositories
- architecture repositories
- collaboration tools
- identity provider

## Governance and Risk Considerations
- human approval for external or material outputs
- clear labeling of generated content
- access control enforcement
- prompt and response monitoring
- usage policy and training
- output quality evaluation
- avoidance of unsupported claims

## Value Drivers
- productivity improvement
- faster drafting and analysis
- reduced context switching
- better consistency
- improved user experience
- reduced cost to serve

## Success Metrics
- time saved per task
- draft acceptance rate
- user adoption
- rework reduction
- output quality score
- user satisfaction
- cycle time reduction

## Common Failure Modes
- unclear user workflow fit
- poor source grounding
- excessive generic outputs
- no human approval model
- low trust from users
- weak adoption and training
